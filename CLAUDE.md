## Commands

```bash
npm run dev      # Start development server (http://localhost:3000)
npm run build    # Production build
npm run start    # Start production server
npm run lint     # ESLint (Next.js config)
```

There is no test suite configured.

## Environment Variables

Required in `.env.local`:
- `MONGODB_URI` — MongoDB connection string
- `JWT_SECRET` — Secret for signing JWTs
- `EMAIL_USER` — Gmail address for OTP emails (optional; mocked if absent)
- `EMAIL_PASS` — Gmail app password
- `ADMIN_SECRET` — optional, 16+ chars; enables the maintenance routes (`/api/seed`, `/api/migrate-categories`, `/api/cleanup-categories`) when sent as the `x-admin-secret` header. Without it they return 404.

## Architecture

**PocketLens** is a personal expense tracker. Stack: Next.js 16 App Router, MongoDB/Mongoose, JWT auth, Redux Toolkit, Tailwind CSS v4.

### Route Structure

- `src/app/(auth)/` — Unauthenticated pages: login, signup, verify (OTP), forgot-password, reset-password
- `src/app/(dashboard)/` — Authenticated pages: add, dashboard, expenses, charts, budgets, calendar, categories, settings; shares the app shell (`layout.jsx`)
- `src/app/(dashboard)/charts/[chart]/` — one full-size chart per page (`balance`, `category`, `subcategory`, `trend`, `monthly`, `budget`, `weekday`; list in `src/components/charts/chartList.js`, views in `ChartViews.jsx`), prerendered; `?range=week|month|year` is read in the browser. The dashboard shows only the 5 stat cards (linking to pre-filtered `/expenses?dateType=range&startDate=…&endDate=…&categoryId=…&subCategoryId=…`) plus tiles that open these charts.
- `src/app/app/` — `/app` entry point: redirects to `/add` on phones/tablets and `/dashboard` on laptops/desktops (used after login, as the PWA `start_url`, and by "Open app")
- `src/app/api/` — API routes grouped by resource: `auth/*`, `expenses/`, `expenses/[id]`, `budgets/`, `categories/`, `users/profile`, `insights/summary`, `insights/charts` (data for one chart, `?chart=`), `income/`, `income/[id]`, `calendar/`, `seed/`

### Middleware / Auth

Middleware lives in **`src/proxy.js`** (Next 16 renamed `middleware.js` to `proxy.js`). It runs on the Node.js runtime and verifies the JWT with `jose`.

Auth flow:
1. JWT is stored in an httpOnly cookie named `token` (7-day expiry).
2. The proxy verifies the cookie on every request (all `/api/*` paths are always matched), redirects unauthenticated users to `/login`, strips any client-supplied `x-user-id`, and injects the real one for downstream API routes. Tokens issued before the user's `passwordChangedAt` are rejected (`src/lib/sessionCheck.js`, cached ~60s).
3. API routes read the authenticated user via `req.headers.get('x-user-id')` — there is no `req.user` or session object.
4. Login/verify set the cookie via `src/lib/session.js` (also sets a readable `logged_in=1` hint cookie used only for UI). Signing uses `src/lib/jwt.js` with `jsonwebtoken` (HS256).
5. Request bodies are untrusted JSON: validate types with `src/lib/validate.js` before using values in queries (prevents NoSQL operator injection), and check category ownership with `src/lib/categoryAccess.js`. OTP handling (attempt limits, resend cooldown) lives in `src/lib/otp.js`.

Signup requires email OTP verification via `nodemailer` before login is permitted.

### Data Layer

- `src/lib/db.js` — Mongoose connection with global caching (`global.mongoose`) to survive hot reloads in dev.
- Models: `User`, `Expense`, `Budget`, `Category`, `Notification` in `src/models/`.
- `Category` has embedded `subCategories`. Expenses reference both `categoryId` and `subCategoryId`.

### State Management

Redux (via `src/store/`) is used **only for UI state** — the single `uiSlice` tracks whether the Add/Edit Expense modal is open and which expense is being edited, plus a `refreshTrigger` counter to signal list re-fetches. Server data is fetched directly in components via `fetch`.

### Key Conventions

- Path alias `@` maps to `src/`.
- Performance: `vercel.json` pins functions to `bom1` (Mumbai), next to the MongoDB Atlas cluster (AWS ap-south-1) — keep them in the same region. Client pages load JSON through `useCachedFetch()` (`src/lib/useCachedFetch.js`, in-memory stale-while-revalidate; cleared on logout).
- The app uses the system UI font (`--font-sans` in `globals.css`); the splash screens use Plus Jakarta Sans. iOS splash screens in `public/splash/` are generated by `scripts/generate-splash.mjs` (needs `chrome-headless-shell`).
- Pie colours come from the user's category colours; sub-categories use shades of their parent's colour (`src/lib/colorShades.js`).
- `"use client"` is required on any component using hooks or browser APIs; layout/page files are Server Components by default.
- UI primitives (Button, Input, Card, Label) are in `src/components/ui/` using `clsx` + `tailwind-merge`.
- The app shell (`src/app/(dashboard)/layout.jsx`) splits at Tailwind `lg` (1024px, `DESKTOP_QUERY` in `src/lib/useOpenAdd.js`): below it, a top bar (logo, settings) + bottom tab bar (Add · Expenses · Dashboard (raised centre) · Budgets · Calendar) with the `/add` screen as home; at/above it, a sidebar with a quick-add pop-up.
- Category icons must be a single emoji: the UI uses `src/components/EmojiPicker.jsx` and the API validates with `cleanEmoji()` in `src/lib/validate.js`.
- Updates: each build gets `NEXT_PUBLIC_APP_VERSION` (Vercel commit SHA; set in `next.config.mjs`). `/api/version` (public) returns the deployed version and `src/components/UpdateNotifier.jsx` shows a "new version available" banner in apps opened on an older build.
- To start adding an entry, call `useOpenAdd()(type, date?)` — it opens the `/add` screen on phones/tablets and the pop-up on desktop. Editing always uses the pop-up (`openAddExpenseModal(expense)` / `openAddIncomeModal(income)`). Both screens share `ExpenseForm` / `IncomeForm`.
